# PhD 科研工作台 v0.7.7

基于现有 Electron、React、TypeScript 和 SQLite 项目增量实现。研究计划、文献阅读、Arxiv Daily、科研成果及论文投稿均可使用。

## 研究手记与成果藏书

研究计划的中央任务区使用按项目分组的低饱和哑光便签，移除斜向反光和纹理，缩短空卡片的高度。左侧栏、任务输入、项目选择与 AI 识别开关保留；便签加号选中该项目并聚焦原输入栏。完成任务在便签中划线保留，可直接恢复。Today Plan 可切换到原有时间安排，日历继续支持分钟级调整。

科研成果以有高低、色彩变化的书脊陈列在书架上，支持原有搜索、排序、年份及期刊筛选。点击或按 Enter 后，书本从书架抽出并翻开封面，展开为暖白色左右等宽双页：左页展示真实 PDF 首页，右页展示标题、作者、发表时间、期刊、分区、DOI、荣誉和备注，底部提供阅读及编辑入口。Escape 或点击空白处可放回书架，焦点恢复后书脊回正。支持深浅色、大字号、最小窗口与系统减少动态效果。完整设计规范见 [研究手记与成果藏书](DESIGN-paper-studio.md)。

## AI 添加计划与页面透明度

设置 → AI 助手默认使用 SiliconFlow，预置接口 `https://api.siliconflow.cn/v1/chat/completions` 和模型 `Qwen/Qwen3-8B`，用户只需要填写自己的 SiliconFlow API Key。也可切换到 OpenRouter 免费或自定义 API；OpenRouter 默认使用 `openrouter/free`，也可填写以 `:free` 结尾的模型 ID，需要用户自己的 OpenRouter API Key。自定义服务兼容 Chat Completions，填写基础地址（如 `https://api.example.com/v1`）或完整 `/chat/completions` 地址；本机 HTTP 服务可不填密钥。保存后可测试连接。API Key 使用系统账户加密保存在本机，页面不回显已保存密钥；修改接口地址时需要重新填写密钥或明确清除。

配置完成后，研究计划顶部输入栏右侧提供可持久化的“AI 识别”开关。开启时，点击“添加”或按 Enter 会识别日期、时间和项目；关闭时，只把输入内容作为任务标题，按当前页面日期和已选项目直接添加，不会请求 AI。输入“今天晚上6点，开组会”后提交，AI 按当前本地日期、时区和项目名称识别计划；未配置服务时会打开配置入口并保留原输入。也可从右下角打开助手，该入口与主面板右边缘对齐，并和侧栏底部外观开关垂直居中。信息明确时直接添加一条共享任务；当天安排显示在全部任务、Today Plan 和日历，其他日期只显示在全部任务和对应日历。没有结束时间时保留为空，不推测时长。未明确日期、上午/下午或项目时追问，支持补充回答和撤销本次添加。批量计划原子保存；同一请求重试不会重复写入。当前不支持通过 AI 修改、删除或设置重复计划。

提交时只有输入内容、本地日期及项目名称和 ID 发给所选服务；不会发送论文、PDF、备注或已有任务列表。联网失败、无效结构、非法日期和时间不会写入任务。语言识别准确性取决于实际模型，请检查添加结果。

设置 → 外观与显示 → 页面透明度支持 0–80%，即时预览、自动保存。侧栏、主面板和卡片同步调整，文字、图标与 PDF 页面保持不透明。旧版背景和字号会保留，缺少透明度设置时默认 25%。各页侧栏移除了“工作空间”，并统一缩减顶部留白。

## 启动

```powershell
npm run dev          # 开发模式
npm run build        # 类型检查并构建
npm start            # 启动构建后的桌面应用
npm run dist:win     # 生成 Windows 运行目录及 NSIS 安装包
```

日常运行入口为 [PhD 科研工作台.exe](<D:/Desktop/Phd Research/release/win-unpacked/PhD 科研工作台.exe>)。本地最新版安装包与可运行目录位于 `release/`；请先保存并退出旧版，再替换运行目录。可运行目录内的依赖需要一同保留。最低窗口尺寸为 1100 × 700 逻辑像素。

## 设置与保存位置

设置中的“外观与显示”支持浅色、深色、跟随系统，以及默认、晨雾、青绿、暮色四种内置背景。可以上传不超过 20 MB 的 JPG/PNG；应用将图片处理为独立本地副本，原图片保留，之后移动原图也不影响已保存背景。界面字号提供 13、14、16、18 四档，立即预览并自动保存；PDF 内容仍使用阅读器自己的缩放。大字号下文献卡片减少列数、长表单可滚动，周日历可横向滚动。

底部顺序为研究计划、文献阅读、科研成果、论文投稿、设置。文献 PDF、科研成果 PDF、Arxiv Daily 三种保存位置可分别选择，系统文件夹选择器支持新建目录。选择完成后检查实际可写性并自动保存；取消或检查失败会保留原设置。“打开”按钮可在文件管理器中打开当前目录。

更改仅影响之后新增的文件，旧文件保留原地址，阅读和导出继续可用。程序保留历史托管目录记录，重启后仍可访问。译文始终生成在对应原文旁，即使原文位于旧目录。请保留仍有文献使用的旧文件夹。进行中的 Arxiv Daily 检索需完成或停止后才能更换其下载目录。

工作台数据也可自定义文件夹。更改时先等待当前保存完成，使用 SQLite 一致性副本校验全部记录，再切换到新数据库；出现错误时保留原数据。数据库单独移动不会改变 PDF 的现有目录。重启通过原配置目录中的小型定位文件 workspace-location.json 找到数据库；外接磁盘不可用时会提示，不会用空库替代。下载或翻译过程中暂不迁移。

### 软件更新

设置页提供“检查并下载更新”。只有点击后，主进程才通过专用 Chromium 网络会话访问固定仓库 `Lzy-shulab/Phd-Research-Table`，继承 Windows 系统代理、PAC 与系统证书设置。程序优先读取 GitHub Latest Release API；匿名 API 额度受限时，自动改读同一仓库 Latest Release 的 `SHA256SUMS.txt`，不把限流误报为普通断网。应用要求发布标签、Windows 安装包文件名和版本号一致，下载后核对文件大小（可取得时）与 SHA-256。信息缺失、地址不属于固定仓库、下载中断或校验失败时停止更新，当前程序保持不变；DNS、超时、代理中断、证书、HTTP 拒绝和访问频率限制分别给出可执行提示。

## 项目与研究计划

- 左侧提供 Today Plan、日历、全部任务。Today Plan 便签显示当天安排及未另排日期的当天截止任务，包括这些任务的已完成状态；时间安排视图聚焦未完成任务。过去和未来任务保留在日历和全部任务中，原日期与分钟时间不变。
- 全部任务默认同时显示未完成和已完成任务，支持“全部状态 / 未完成 / 已完成”筛选，以及完成、恢复与排序。
- 每个新计划必须属于一个项目。项目仅作为任务归属和便签分组，不再提供独立项目页或左侧项目分类；Today Plan、全部任务与日历始终汇总所有项目，侧栏计数也始终按全部项目计算。
- 全部任务以不同颜色的项目便签显示所有任务，包括归档项目、已完成任务、未来任务和旧版待归属记录；支持按任务内容搜索、状态筛选和排序。便签右上角可管理项目。
- 快速新建栏始终提供“新建项目”。创建后会直接选中新项目；只有一个未归档项目时仍会自动选择，否则需要手动选择。
- 快速输入按 Enter 保存，Ctrl+N 聚焦新建入口。Today Plan 新任务默认安排到今天；未来任务可在日历中直接创建，或在全部任务的详情中指定日期。
- 原有无项目记录保留，在全部任务中显示“待归属项目”，可在详情中补充。不会按标题猜测归属。
- 归档项目保留所有任务与历史；恢复后可新增任务。有任务的项目在删除前必须选择另一个未归档项目接收任务，转移与删除在一个数据库事务内完成。
- 任务文本使用原有串行保存队列；关闭窗口会等待保存，保存失败时保留窗口和草稿。支持完成、恢复、手动排序与键盘排序。

日历保留日/周视图、跨列移动、框选、上下边缘调整、边界滚动和 Escape 取消。所有输入及拖动均支持任意一分钟：例如 09:17–10:43。每小时 72 CSS px；指针按 1 分钟取整，不吸附到 15/30/60 分钟。时间必须在同一自然日内且结束晚于开始，最大结束时间为 23:59。旧的只有开始时间的任务保留空结束时间，显示标记不作为真实时长写入。

## 文献阅读

普通文献和 Arxiv Daily 卡片底部统一为“原文／已翻译或未翻译／中英摘要”三个入口，翻译状态合并进按钮，取消重复状态行。已有译文时打开中英对照 PDF，未翻译时才加入全文翻译队列，排队、进度与失败重试也在该入口显示。点击 arXiv 卡片封面或标题默认打开中英摘要，以左右两栏对照原文与中文标题、摘要，另有“阅读原文”入口。首次打开使用“设置 → AI 助手”的接口翻译标题与摘要，之后读取本机缓存，也可重新翻译。普通 PDF 从前三页提取有明确起止标记的摘要，未可靠提取时提示粘贴原文摘要，不用正文生成总结。只发送当前题目和原文摘要，不发送笔记、项目或其他论文，不修改全文翻译和阅读进度。没有配置 AI 或翻译失败时仍显示已有英文内容。

左侧自定义文件夹按期刊、会议或研究方向组织，中间显示 PDF 首页卡片。支持明确的顶层、二级和三级文件夹；第一、二层文件夹行可直接新建下级，第三层不再提供下级入口，数据库也拒绝超过三级的移动或新建。支持改名、移动和删除，父文件夹包含所有后代文件夹的文献。删除文件夹后，该文件夹的文献进入未分类，直接子文件夹成为顶层文件夹。

点击“添加文献”或拖入 PDF，选择归属及是否自动翻译。单篇上限 100 MB，支持批量添加。应用复制文献至自己的管理目录，按 SHA-256 内容去重，不改动原始上传文件。重复添加保留原有文献及文件夹。

卡片展示实际首页、题名、作者、年份、期刊或会议、阅读页码和翻译状态。导入后自动在本机读取 PDF/XMP 元数据及首页排版，并通过 DOI 或高置信标题向 Crossref 查询公开书目。只发送 DOI/标题，不上传 PDF 全文；可在设置关闭联网补全。相近但不能唯一确认的匹配不会自动采用，缺失字段会提示手工补充；失败时可重新识别。手动修改或清空过的字段不会被自动覆盖。扫描 PDF 若无可提取文字，保留文件名并提示补充，本功能不执行 OCR。支持搜索标题、作者、期刊、笔记，按状态筛选与排序，编辑阅读笔记和归属。

“原文”与“中英对照”打开同一阅读器，支持文字选择、页码跳转、缩放、方向键/PageUp/PageDown 翻页。原文和译文分别保存阅读位置。卡片最下方的渐变进度条按原文/译文中的最远阅读位置记录，翻回前页不会倒退；它表示阅读位置，不表示逐页完整阅读或理解程度。导出按钮保存当前 PDF。移除文献会将应用托管的副本移入 Windows 回收站，原始上传文件保留。

## 论文投稿

投稿时间和稿号在标题下方以两个独立信息块展示，数值加大加粗，长稿号自动换行且可选择复制。缺失字段显示“尚未投稿”或“未填写”，不会推测日期或稿号。

在“科研成果”右侧进入论文投稿。每条记录代表向一家期刊或会议的一次投稿，包含论文标题、期刊/会议、稿号、用户自定义状态及其日期、返修截止日期、提前提醒天数和备注。状态名称可直接使用期刊系统原文，例如 `Submitted to Journal`、`With editor`；不再限定为固定的中文状态集合。转投时新建一条记录，保留上一轮经历。支持搜索标题、期刊、稿号、备注及状态名称，按当前状态筛选，并按更新时间、首个状态日期或返修期限排序。

时间线只展示实际添加的状态，不生成尚未发生的占位阶段。每个状态保存明确的日历日期，首个状态日期同时作为卡片中的投稿时间，最新状态名称作为当前状态。状态可新增、删除、改名和上下调整顺序；日期必须从早到晚。没有状态时显示左对齐提示，少量状态使用紧凑的左对齐时间线，数量增加后逐步扩展，约十个状态时自适应卡片可用宽度。

顶部统计累计投稿、本月进展、返修截止和已记录阶段总数；尚无状态的记录不计入累计投稿。时间线表示已经记录的流程节点，不推断录用概率或阶段耗时。旧版固定状态和阶段事件在 migration 0005 中原样保留，并额外转换为可编辑的自定义状态节点；迁移不会猜测期刊特有的英文名称。

设置了返修截止日期并开启提醒时，在提前天数窗口及逾期期间每天最多发送一次系统通知；提醒不再依赖某个固定状态名称。应用启动时补查，完全关闭期间不发送，也没有注册后台系统计划任务。系统通知不可用时仍在页面显示截止事项。

## 本地翻译环境

首次启动不再假定电脑上存在开发者专用的 `D:\Python\...` 路径。未检测到引擎时，自动翻译保持关闭；点击文献卡片的“翻译”或“重试”会先打开“文献翻译设置”，不会先把文献标记为翻译失败。

文献翻译设置提供两种安装方式：点击“一键安装官方引擎”，从 [PDFMathTranslate-next v2.9.0 官方 Release](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next/releases/tag/v2.9.0) 下载首次使用推荐的 Windows with-assets 包（BabelDOC 0.6.4，约 592 MB），或选择已有环境。自动安装支持进度显示、暂停后断点续传，并在解压前核对官方发布的 SHA-256 `6916a2f299b029cfb75803c780528088d93e7694d5597c4250ba2dcf5598f1d8`；校验不一致时不会启用文件。解压时拒绝越界路径、符号链接、异常文件数量和异常展开体积。引擎保存在当前 Windows 账户的工作台程序数据目录中，不写入文献数据库或 PDF 保存目录。

“选择已有环境”同时支持官方便携版中直接包含 `pdf2zh_next.exe` 的文件夹，以及旧版包含 `zotero-pdf2zh-next-venv/Scripts/pdf2zh_next.exe` 的 Server 根目录。PDFMathTranslate-next 是独立的 AGPL-3.0 第三方项目，工作台按用户操作从其官方发布页下载，工作台安装包本身不捆绑该大型引擎。

普通文献上传沿用原有自动翻译设置。Arxiv Daily 下载与科研成果上传始终保留原文，不自动翻译。文献卡片的“翻译”按钮可以按需加入队列。原文立即入库，后台串行处理，完成后同一张卡片上的“翻译”直接打开中英对照 PDF。生成结果为左英文、右中文的并排 PDF。失败或关闭中断时保留原文并提供重试；尚未开始的队列在下次打开时继续。

**PDF 解析与排版在本机执行，文本通过所选翻译 API 联网处理，属于本地运行加联网翻译。** 翻译质量和耗时受文献内容、网络和翻译服务影响。v0.6.1 已用默认的 PDF2zh 公益免费服务和合成英文样例完成真实翻译验证；扫描 PDF、加密 PDF 和复杂整篇论文的翻译质量未逐一验证。

文献页右上角“文献翻译设置”内置四套配置：PDF2zh 公益免费服务、Gemini 2.5 Flash-Lite、OpenRouter 免费模型路由、SiliconFlow 自有额度。还可以新增任意 OpenAI 兼容接口，编辑名称、模型和 Base URL，并选择当前使用项。Base URL 填写到 `/v1`，不要包含 `/chat/completions`。

默认启用 SiliconFlow 自有额度，预置 Base URL `https://api.siliconflow.cn/v1` 和模型 `Qwen/Qwen3-8B`，用户只需要填写自己的 SiliconFlow API Key。PDF2zh 公益免费服务无需密钥；Gemini、OpenRouter、SiliconFlow 和自定义接口需要用户自己的密钥；密钥由当前 Windows 账户的安全存储加密，页面和 IPC 只显示“是否已保存”，不会回显明文。Gemini 官方提供免费层，但[官方地区列表](https://ai.google.dev/gemini-api/docs/available-regions)不包含中国大陆；OpenRouter 的 `openrouter/free` 会在当前免费模型中动态选择，并不保证固定为 Gemini。所谓“免费”均受服务商实时额度、限流和可用性约束，不代表永久免费。

每项任务先使用旧环境中的 `config/config.toml.example`，没有外部模板时使用工作台随附的 PDF2zh 2.9.0 配置架构；随后只把当前选择的配置写入任务副本。外部模板不会被修改，模板内其他服务的密钥不会被复制到任务目录。切换配置从下一项翻译任务开始生效。

应用通过随程序打包的进度适配脚本运行现有 PDF2zh Next 环境，每个任务使用独立配置副本，不调用旧服务的初始化逻辑。顶部翻译条显示引擎实际报告的总进度、当前阶段、阶段处理数量和已用时；准备阶段没有百分比时显示等待状态，不按时间虚构百分比。结果通过 PDF 校验后才变为可阅读的中英对照版。若旧环境缺少适配脚本所需的 Python 入口，则回退到原 CLI，保持翻译能力，此时不显示虚构的百分比。

## Arxiv Daily

入口固定在文献左侧“未分类”下方，与全部文献及自定义文件夹分开显示、计数和筛选。点击“立即检索”可手动运行，“检索设置”可修改研究关键词、回看天数、每日上限，以及开关每日自动检索。

默认沿用旧工程的高光谱、Mamba/状态空间模型和多模态检测方向，回看 14 天、每天最多下载 5 篇未下载文献。默认在每天首次打开工作台时自动执行；应用持续运行时，每分钟检查一次是否跨天。应用完全关闭时不执行，也没有注册 Windows 定时任务。当天自动尝试失败会显示原因，点击“立即检索”可重试。

每行英文词组代表一个方向，用 AND 连接同一方向内需同时满足的词组。搜索标题和摘要，按关键词匹配程度排序，同分时较新的论文优先。使用本地关键词排序，不调用旧脚本中的 SiliconFlow 评分，也不抓取出版社、Crossref 或其他网站。每组最多检查 300 条近期候选，避免宽泛关键词产生无限分页。

只访问 arXiv API 和 arxiv.org PDF。请求串行并至少间隔 3.1 秒；同一天、相同检索设置的元数据会缓存。按不含版本号的 arXiv 编号去重，因此同一论文更新版本不会作为新论文重复下载。每日上限跨重复点击与重启累计；删除文献后仍保留下载历史，避免被次日重新下载。无新论文时不凑满数量。网络错误、无新结果和 PDF 下载失败分别显示。

下载文件按收录日期保存在本工作区的 `工作台数据/Arxiv Daily/日期/文献ID/source.pdf`。可通过“下载目录”打开。论文保持“未翻译”；点击“未翻译”后才生成同目录下的 `bilingual.pdf`。手动添加的普通文献及个人成果不会被自动移动至这里。arXiv 默认使用系统代理；代理连接中断时通过独立网络会话尝试直连同一官方地址，成功路径暂记 10 分钟，不修改 Windows 代理或其他服务的网络配置。限流、证书错误和主动取消不会触发该回退。

参考：[arXiv API 手册](https://info.arxiv.org/help/api/user-manual.html)与[使用条款](https://info.arxiv.org/help/api/tou.html)。旧方向参考 `D:/Desktop/Arxiv Paper/Project/scripts/arxiv_daily.py` 和用户指定旧工程中的 `research_cockpit/panels/direction.py`；旧工具与配置未修改。

## 科研成果

点击“添加成果”，选择一份已发表论文 PDF，自动读取 PDF/XMP 与首页资料，再按设置通过 DOI 或标题查询 Crossref，将标题、作者、期刊或会议、DOI、发表时间填入表单。可继续修改并核对后保存；编辑已有成果时也可重新识别。只发送 DOI 或标题，不上传 PDF 全文。仅知道年份或月份时按对应精度保存，不补造具体月日。期刊分区、JCR 分区、论文荣誉和备注仍由用户填写。期刊分区保留 1–4 区、非 SCI，并增加 EI、中文核心、大学学报；按手工填写内容展示，不自动推断。论文荣誉可多选 ESI 高被引、ESI 热点、封面论文和最佳论文，分别使用趋势、火焰、封面和奖杯图标；荣誉不会根据期刊或引用数据自动推断。备注可记录采用的分区年份与作者贡献。DOI 可留空，填写 DOI 链接时会提取规范编号。

中间的成果书架以书脊展示论文，抽出后以双栏卡片展示真实 PDF 首页及完整发表资料，包括论文荣誉。支持阅读与重新编辑。左侧自动生成发表年份和期刊筛选，可组合筛选。成果只在科研成果页面展示，不混入全部文献或 Arxiv Daily。同一 PDF 可以分别作为阅读文献和个人成果保存，彼此编辑、阅读和删除独立。

数据库 migration 0002 增加文献归属、arXiv 与发表信息、下载历史表；原有文献默认归入普通文献库，原文件路径、分类、译文、笔记、阅读位置均保留。内容哈希去重调整为各归属内去重。migration 0003 增加投稿及阶段历史表、书目识别状态与单独的阅读进度字段，按旧阅读页码初始化进度。migration 0004 为论文增加 JSON 文本形式的荣誉列表，旧记录默认得到空列表。migration 0005 增加可排序的投稿自定义状态表，并从旧阶段事件回填状态名称和日期；旧投稿行与旧事件不改写。0000–0004 未改写，既有任务和项目字段不变。日期与时间仍为 YYYY-MM-DD、HH:mm 本地时间文本，审计时间仍为 ISO UTC。

开发和打包版本均支持 WORKBENCH_DATA_DIR 指定隔离配置目录。当前工作区通过系统配置目录中的定位文件找到上述数据库。`npm run dev:seed` 使用独立演示数据，仅空演示库会填入示例。请使用根目录“启动科研工作台”或 release 中的当前程序。

原有 Zustand 保存队列、typed preload、IPC、Repository 结构延续。LibraryService 管理 PDF、翻译队列及独立的 ArxivDailyService。PDF.js worker、字体、CMaps 和 WASM 随应用打包；阅读器不依赖外部 CDN。生产渲染层不允许联网，arXiv 和 Crossref 访问由主进程的独立研究 session 发起，只允许已配置的 HTTPS 域名；翻译网络访问由独立 Python 引擎发起；软件更新由主进程的独立更新 session 访问固定 GitHub API、Latest Release 校验文件和该仓库的 Release 下载地址。

## 视觉与操作

五个主页面共用顶部“每日科研”鼓励语，可点击查看完整语句及来源。应用从[一言公开句库](https://sentences-bundle.hitokoto.cn/)读取已筛选的学习、思考、科学探索与坚持相关语句，按本机日历日期在零点更新，同一天保持同一句，避免近期重复。后台运行时由主进程定时更新，休眠唤醒或重新打开时补查；完全退出期间不会主动联网。断网保留上一句并标注原来源日期，首次离线使用明确标注的工作台原创语句，恢复网络后重试。出处信息沿用来源平台收录，不额外声称名人出处已经核验。

界面默认基础字号为 14px，可在设置切换 13/14/16/18px；标题、正文、辅助信息按层级一起调整。PDF 文档内容仍由阅读器缩放控制。长语句在窄窗口中省略，点击可以完整阅读；长表单和页面保留滚动区域。

应用按 apple-design 使用静态低饱和背景、毛玻璃侧栏和底部导航、适度透明的文献及成果卡片。PDF 像素保持不透明，确保原始内容清晰。选中态使用无反弹弹簧，详情面板可连续切换；减少动态效果、减少透明度和增强对比度设置有对应适配。PDF 文字层样式限制在阅读器内，避免影响主导航。
